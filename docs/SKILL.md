# 代码修改规范与技能指南

## 📋 适用范围
---

在执行任何代码修改前，必须阅读并遵循本文档的规范。

---

## 🔧 代码修改规范

### 1. 方法复用原则

**在修改代码前，必须先检查现有代码：**

- ✅ **如果已有相关功能的方法**：
  - 在该方法中直接修改
  - 或者删除旧方法后重新创建
  - **禁止创建重复的方法**

- ✅ **如果没有相关功能的方法**：
  - 可以新建一个方法
  - 确保方法命名清晰、符合现有代码风格

**示例：**
```cpp
// ❌ 错误做法：创建新方法 initSpectrumChartNew()
// ✅ 正确做法：在原有的 initSpectrumChart() 中修改
```

---

### 2. 代码测试要求

**修改完成后的流程：**

1. **自行测试代码**
   - 确保代码能够编译通过
   - 验证功能逻辑正确
   - 检查是否有语法错误

2. **测试方式**
   - 优先使用项目自带的编译工具测试
   - 如果难以直接测试，可以创建 Python 脚本辅助测试
   - 测试完成后，**必须删除临时测试脚本**

3. **反馈规则**
   - ✅ 测试通过后，向用户反馈修改内容
   - ❌ **不要生成 Markdown 文档**（除非用户明确要求）
   - 简洁说明修改了什么、为什么修改

**示例流程：**
```
1. 修改代码
2. 编译测试（或创建测试脚本）
3. 确认无错误
4. 删除测试脚本（如果有）
5. 向用户反馈修改内容
```

---

### 3. 新功能集成指南

**当用户要求添加新功能时：**

1. **分析现有代码结构**
   - 查看相关的类和方法
   - 识别需要整合的参数
   - 确定需要的辅助功能

2. **提供集成建议**
   - 列出需要整合的参数
   - 说明需要添加的辅助方法
   - 指出可能影响的其他模块
   - 建议最佳实现方案

3. **示例提示格式**
   ```
   要添加此功能，需要：
   
   参数整合：
   - 在类中添加成员变量 m_xxx
   - 在构造函数中初始化
   
   辅助功能：
   - 需要创建 initXxx() 方法
   - 需要在 UI 中添加对应控件
   
   影响模块：
   - integration.h - 添加声明
   - integration.cpp - 实现功能
   - integration.ui - 添加 UI 控件
   
   建议方案：
   - 方案A：...
   - 方案B：...（推荐）
   ```

## 📝 代码风格规范

### 命名规范
- **成员变量**：`m_variableName`（小驼峰，m_ 前缀）
- **方法名**：`methodName()`（小驼峰）
- **类名**：`ClassName`（大驼峰）
- **常量**：`CONSTANT_NAME`（全大写，下划线分隔）

### 注释规范
- 使用中文注释说明关键逻辑
- 每个功能模块前添加分隔注释：`// ========== 模块名 ==========`
- 复杂逻辑必须添加注释说明

### 代码组织
- 相关功能的方法放在一起
- 使用分隔注释区分不同功能模块
- 保持代码缩进一致（4个空格）

---

## ⚠️ 禁止事项

1. ❌ **禁止创建重复方法**
   - 如果功能已存在，必须在原方法中修改

2. ❌ **禁止未测试就反馈**
   - 必须确保代码能够编译通过

3. ❌ **禁止随意生成文档**
   - 除非用户明确要求，否则不生成 MD 文档

4. ❌ **禁止保留测试文件**
   - 测试脚本使用后必须删除

---

## ✅ 最佳实践

### 修改代码前
1. 阅读相关代码，理解现有逻辑
2. 检查是否有现成的方法可以复用
3. 规划修改方案

### 修改代码时
1. 在原有方法中修改（如果存在）
2. 保持代码风格一致
3. 添加必要的注释

### 修改代码后
1. 自行测试编译
2. 验证功能正确性
3. 清理临时文件
4. 简洁反馈修改内容

---

## 📚 项目特定规范

### 设备类
- 所有设备类继承自基类
- 使用信号槽机制通信
- 状态更新通过 `statusChanged` 信号

### UI 交互
- 按钮槽函数命名：`on_btnXxx_clicked()`
- 输入框获取：`ui->lineEditXxx->text()`
- 状态指示器：`updateStatusIndicator()`

### 预设管理
- 振镜页和位移台页使用统一的预设结构
- 通过 `PresetPageType` 枚举区分页面
- 使用辅助方法获取对应的成员变量

---

## 🎯 总结

**核心原则：**
1. **复用优先** - 不创建重复方法
2. **测试先行** - 确保代码无错误
3. **简洁反馈** - 不生成多余文档
4. **提前规划** - 新功能先分析再实现

**记住：代码质量 > 代码数量**
